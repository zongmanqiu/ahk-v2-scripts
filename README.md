# ahk-v2 脚本仓库

AHKDeck 的**官方脚本**仓库：每个脚本一份纯 AHK v2 源码，可搭配 AHKDeck 使用，也可用原版
AutoHotkey v2 独立运行。脚本与宿主**分离**——本仓库是脚本的唯一真源，宿主只负责运行。

- AHKDeck：面向 Windows x64 的 AutoHotkey v2 脚本工作台，集成脚本管理、编辑运行、日志查看与 MCP AI 接入。

## 怎么用

- **AHKDeck 内**：把 `.ahk` 放进宿主的 `Scripts` 目录（或在宿主里添加脚本），运行后脚本的托盘菜单
  会被宿主镜像成右键子菜单，点菜单项即入口；**窗口型脚本**（文件时间修改、文件哈希、硬件信息、文件解锁、右键菜单整理、软件卸载）则直接弹出窗口。宿主关闭时脚本一并结束。
- **窗口型脚本**：文件时间修改、文件哈希、硬件信息、文件解锁、右键菜单整理、软件卸载不使用托盘菜单，运行后直接出现窗口；
  以文件时间修改为例，把文件或文件夹拖进路径列表，设好三种时间后点「更新时间」执行。窗口关闭即退出。
- **独立运行**：安装 [AutoHotkey v2](https://www.autohotkey.com/)（x64）后双击脚本，或
  `AutoHotkey64.exe 脚本.ahk`。所有脚本不依赖宿主私有 API，独立运行功能完整。
- **命令行分支**（无 GUI 入口，用独立解释器调用）：夜灯、打开方式清理、文件哈希、硬件信息、防休眠、文件解锁、右键菜单整理、软件卸载
  均带 `--selftest [输出路径]`，只动各自的自建数据、结束即清理；`rc=0` 全绿。另有
  - `打开方式清理.ahk --report [输出路径]`：只读扫描，输出逐来源行数/耗时等读数。
  - `软件卸载.ahk --report [输出路径]`：只读扫描，输出三源键数/扫描与分类耗时等读数。
  - `硬件信息.ahk --dump [输出路径]`：导出完整硬件规格读数。

## 想知道｜去哪

| 想知道 | 去哪 |
|---|---|
| 某个脚本的功能/入口/写入位置/风险 | 该脚本文件夹下的 `info/README.md` |
| 某个脚本各版本改了什么 | 该脚本文件夹下的 `info/HISTORY.md`（只增不改） |
| 目录怎么组织、头部块怎么写、注释/版本/测试/出货规矩 | [`开发指南.md`](开发指南.md) |
| 脚本机器清单（版本/作者/release 附件地址，宿主下载用） | [`scripts.json`](scripts.json)（由 `tools/make_index.py` 生成） |
| 某脚本的版本历史与双仓库下载地址 | `history/<英文id>.json`；宿主在「脚本详情」里给出可点击的 Gitee / GitHub 链接 |
| 某个脚本自己的测试 | 该脚本文件夹下的 `test/`，跑 `python scripts/<名>/test/run.py`（只测这一个脚本） |
| 单脚本静态检查（调色板/字号/版本/出货件一致） | `python tools/ui_static.py <脚本名>`（必须给名字，没有「跑全部」） |
| 单脚本码表检查（枚举码是否与 SMBIOS/微软枚举逐项一致） | `python tools/check_codes.py <脚本名>`（同上，必须给名字；`--from-dmidecode <dmidecode.c>` 可校验工具自己的权威表） |
| 某个脚本复刻/移植了哪个项目、来源与许可 | 该脚本头部注释与 `info/README.md` |
