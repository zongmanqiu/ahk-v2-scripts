# 右键菜单整理

右键菜单用久了会被各种软件塞满。这个脚本按你**实际右键的 3 种场景**列出菜单项——既有系统/软件装进注册表的静态项，也有 7-Zip、ima、360、Unlocker 这类 COM 扩展——逐项**隐藏**掉你不想要的，或者把常用的**置顶**——只写当前用户（HKCU），随时能恢复原样。

## 功能

- 左侧三个入口，覆盖日常全部右键场景：
  - **拖入文件/文件夹**：把文件或文件夹拖进左边的框，脚本自动判类型、展开它的菜单来源（文件=`*`+扩展名+关联程序+所有对象；文件夹=`Directory`+`Folder`+所有对象）。同一个菜单项来自多处时会合并成一行，隐藏时对每个来源都生效。
  - **桌面空白处**：桌面背景右键的菜单（新建、个性化、壁纸等）。
  - **文件夹空白处**：在文件夹里点右键（不是在文件上）的菜单。
- 右侧列出该场景的**全部**菜单项，五列显示：
  - **顺序**：这一项在真实右键菜单里的次序，从 1 连续编号。底部「上移 / 下移」改的就是它，改完真实菜单立刻跟着变。
  - **菜单项**：显示名称解析成人话，`@shell32.dll,-8506` 这类间接串会转成可读文字；系统扩展按 CLSID 友好名显示（发送到/新建/打开方式/授予访问权限/NVIDIA 控制面板…），`open` 这类键值全空的内建动词显示"打开/编辑/删除"等真实菜单用语。
  - **来源**：`静态`（注册表 verb）或 `COM`（shellex 扩展）。
  - **状态**：**显示** / **已隐藏**（本脚本隐藏的）/ **系统隐藏**（HKLM 里带隐藏标记，零提权删不掉）。
  - **位置**：默认 / 置顶 / 置底（COM 项由 DLL 动态绘制，不支持位置，显示 `—`）。
- **表头可点击排序**：点任意列表头按这列排序，列名后出现 ↑ / ↓ 指明当前排序列与方向；同一列再点一次反向。默认按「顺序」升序，也就是脚本推断的真实菜单次序。
- **「隐藏不可见项」勾选框**（默认勾上）：只列真实右键菜单里会出现的项——已隐藏的、系统打了隐藏标记的、以及按住 Shift 才显示的 `Extended` 项都不显示。取消勾选可以看见全部注册项（含系统隐藏的那些）。
- 三级二级内容（1.4.0）会在父项下面**缩进列出**（只读，不能在这里增删）：
  - **发送到**：数据源是 `%APPDATA%\Microsoft\Windows\SendTo` 文件夹。
  - **新建**：数据源是全机的 `ShellNew` 登记项，名称与资源管理器「类型」列一致。
  - **包含到库中**：数据源是 `%APPDATA%\Microsoft\Windows\Libraries\*.library-ms`。
  - 7-Zip、授予访问权限、上传至 ima 的子菜单由各自 DLL 动态生成，注册表里没有子项数据，列不出来。
- 选中一项后，底部按钮只做三件事：
  - **隐藏 / 显示**：同一个按钮，选中的项现在可见就是「隐藏」，已隐藏就是「显示」。静态项写隐藏标记；COM 扩展按 CLSID 加入/移出 Blocked 名单，全局生效。
  - **上移 / 下移**：把静态项**逐位**往上/往下挪一格（不是置顶/置底），挪完真实右键菜单里的次序同步变化。COM 项与二级项没有独立位置，不参与调序。
  - **刷新**：重新读一遍注册表。
- 改完立即广播 `SHChangeNotify`，绝大多数情况不用重启资源管理器。

## 入口

- 主窗口：左侧选场景或拖入文件 → 右侧选菜单项 → 底部按钮操作。
- `--selftest [输出路径]`：无 GUI 分支，默认写 `右键菜单整理\selftest-result.txt`。
- `--probe verb <位置suffix> <verb> <动作>` / `--probe com <CLSID> <hide|show>` / `--probe roots <场景key> <结果文件> [拖入路径]` / `--probe items <场景key> <结果文件> [拖入路径]` / `--probe order <场景key> <结果文件> <verb,verb,…>` / `--probe restore <场景key> <结果文件>` / `--probe vals <HKCR键路径> <结果文件>`：实机回归用；日常不用。

## 写入位置

只写 HKCU，HKLM 原键一个字节都不动：

- **静态项隐藏**：`HKCU\Software\Classes\<位置>\shell\<菜单项名>` 写 `ProgrammaticAccessOnly = ""`；恢复即删这个值。菜单项来自多个位置时，每个位置的影子键都写，才不会被别的来源重新带出来。
- **静态项位置**：同键写 `Position = top / bottom`；恢复默认即删这个值。位置根不含 `\shell`（如 `*` / `Directory\Background`）。
- **静态项顺序**：shell 按 verb **键名字母序**排静态项（与显示名无关），`Position` 只有顶部/底部两档，没有「第 N 位」。所以逐位调序靠「接管」：把该根下的静态 verb 复制成 `HKCU\Software\Classes\<位置>\shell\p0001#<verb>`、`p0002#<verb>`…（前缀 `p` 排在 `open` 之后），原件只写 `ProgrammaticAccessOnly` 让位、显示名与命令都不动。副本编号就是真实次序。恢复 = 删掉所有副本 + 清掉 `ProgrammaticAccessOnly` 与 `_AhkDeckTakenOver` 两个标记。
- **COM 扩展隐藏**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Shell Extensions\Blocked` 写一个值名为 CLSID 的空串；恢复即删该值。

这些值在 `HKCR` 合并视图里可见，于是既能盖住 HKLM 的菜单项，又不破坏它原本的显示名和命令。
`--selftest` 结果写 `scripts/右键菜单整理/右键菜单整理/selftest-result.txt`（同名文件夹，运行时自建，不进仓库）。
GUI 事件层抛的异常会落到同一目录的 `error.log`，排查「点了没反应」先看它。

## 风险与不做

- **不永久删除**任何菜单项、不改命令、不碰文件关联、不提权、不写 HKLM。隐藏和位置都是可逆的。
- **系统级隐藏的项恢复不了**：若某项的隐藏标记写在 HKLM（如 `HideBasedOnVelocityId`），零提权删不掉，脚本会如实提示"需管理员权限"，绝不谎称已恢复。
- **系统共享的 COM 扩展拒隐藏**："共享 / 投射到设备 / 还原以前的版本 / 照片编辑 / 包含到库中" 这类 CLSID 由多个功能共用，Blocked 会连带弄坏系统菜单，脚本一律拒写。7-Zip、ima、360、Unlocker 这类独立扩展不受限。
- **不碰 `open` / `edit` 这类打开动词**：它们是文件关联的关键，脚本对这两个 verb 一律不写。
- **不写 `CommandFlags`**：那是 Windows 的功能位掩码，不是开关，写错会弄坏菜单；本脚本只读取它来判断是否已隐藏。
- **不做 Win11 打包命令（IExplorerCommand）**：那是稀疏 MSIX 包 manifest 里的动态命令，不属于注册表静态项，本脚本不覆盖。
- **读注册表来源，不读渲染后的菜单**：拖入文件后调 Windows 真实菜单接口（IContextMenu）虽然所见即所得，但 COM 项是 OWNERDRAW、连 verb 都没有，静态项也只有 verb 没有位置根——无法反推该写哪个键来隐藏。所以本脚本读注册表来源并按对象类型合并，交互是 3 种、读取引擎仍是来源表。
- 菜单项显示名取自注册表；个别项的中文名由系统资源串解析，解析不出来时回退为注册表名；常见系统扩展（发送到/新建/打开方式/上传至ima知识库…）走友好名映射。
- **顺序**：静态项的顺序可以真的改，代价是该根下的静态项会被「接管」——原件留 `ProgrammaticAccessOnly` 让位、由 HKCU 副本出面，所以被接管的项在注册表里会看到 `p000N#…` 这类键名，这是设计如此（脚本里就叫「副本」）。COM 扩展之间、以及菜单里那些不在注册表里的内建命令（剪切/复制/粘贴/重命名/属性…）的先后，脚本改不了。接管只影响当前用户，`--probe restore` 或手工删副本即可完全还原。
