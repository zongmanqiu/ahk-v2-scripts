# 右键菜单整理

右键菜单用久了会被各种软件塞满。这个脚本按你**实际右键的 3 种场景**列出菜单项——既有系统/软件装进注册表的静态项，也有 7-Zip、ima、360、Unlocker 这类 COM 扩展——逐项**隐藏**掉你不想要的，或者把常用的**调到合适的位置**——只写当前用户（HKCU），随时能恢复原样。

## 功能

- 左侧三个入口，覆盖日常全部右键场景：
  - **拖入文件/文件夹**：把文件或文件夹拖进左边的框，脚本自动判类型、展开它的菜单来源（文件=`*`+扩展名+关联程序+所有对象；文件夹=`Directory`+`Folder`+所有对象）。同一个菜单项来自多处时会合并成一行，隐藏时对每个来源都生效。
  - **桌面空白处**：桌面背景右键的菜单（新建、个性化、壁纸等）。
  - **文件夹空白处**：在文件夹里点右键（不是在文件上）的菜单。
- 右侧列出该场景的菜单项，五列显示：
  - **顺序**：这一项在真实右键菜单里的次序，从 1 连续编号。底部「上移 / 下移」改的就是它，改完真实菜单立刻跟着变。
  - **菜单项**：显示名称解析成人话，`@shell32.dll,-8506` 这类间接串会转成可读文字；系统扩展按 CLSID 友好名显示（发送到/新建/打开方式/授予访问权限/NVIDIA 控制面板…），`open` 这类键值全空的内建动词显示"打开/编辑/删除"等真实菜单用语。
  - **来源**：`静态`（注册表 verb）、`COM`（shellex 扩展）、`内建`（Windows 自己往菜单里放的项，注册表里没有可写的键——剪切/复制/删除/重命名/属性/创建快捷方式，以及资源管理器自己补的「在新窗口中打开」）、`二级`（父项的子菜单）。
  - **可改**：这一行到底能做什么，**看表就知道，不用点一次被拒一次**：
    - `隐藏·调序`：静态项且自带显示名（MUIVerb），隐藏和上移/下移都行。
    - `仅隐藏`：能隐藏，但位置动不了——COM 扩展（位置由它的 DLL 决定）、或显示名由 Windows 按键名硬编码的静态项（改名会显示成 `p0001#open`）。
    - `只读`：什么都改不了——二级项、`内建` 项（注册表里没有可写的键）、`打开`/`编辑` 动词（脚本明令不动）、以及系统共享 CLSID（零提权禁用会连带坏系统功能）。
  - **状态**：**显示** / **已隐藏**（本脚本隐藏的）/ **系统隐藏**（HKLM 里带隐藏标记，零提权删不掉）/ **菜单外**（注册表里登记了，但这次 shell 根本没往菜单里放）。
- **表头可点击排序**：点任意列表头按这列排序，列名后出现 ↑ / ↓ 指明当前排序列与方向；同一列再点一次反向。默认按「顺序」升序。
- **「隐藏不可见项」勾选框**（默认勾上）：只列真实右键菜单里会出现的项——已隐藏的、系统打了隐藏标记的、标着「菜单外」的、以及按住 Shift 才显示的 `Extended` 项都不显示。取消勾选可以看见全部注册项。
- 二级内容会在父项下面**缩进列出**（只读，不能在这里增删）。展开方式分两类：
  - **发送到 / 新建 / 包含到库中**：以数据源为准。这三项的真实菜单树是延迟填充或当场生成的，读回来经常只有一两条（1.6.3 修的就是「发送到」只剩一条），所以直接列数据源：
    - **发送到**：`%APPDATA%\Microsoft\Windows\SendTo` 文件夹，显示名走 shell 的本地化名（`压缩(zipped)文件夹` / `桌面快捷方式` / `邮件收件人`），不是文件名；**只列注册了发送处理器的项，`SendTo` 里的 `.lnk` 快捷方式不进菜单**（实测 Win11：8 项里菜单只出现 4 项，差的 4 个全是 .lnk）。
    - **新建**：全机 `ShellNew` 登记项，含挂在 ProgID 下面那一层（Word/Excel/PowerPoint），名称与资源管理器「类型」列一致。只列真正带 `NullFile/Data/FileName/Directory/Command/Handler` 之一的键——空的 `ShellNew` 键（如 AMOS/RAR）shell 自己也不列，脚本同样跳过。
    - **包含到库中**：`%APPDATA%\Microsoft\Windows\Libraries\*.library-ms`。
  - **7-Zip（含 `CRC SHA` 再下一层）、授予访问权限、上传至 ima**：这些由 DLL 当场生成、没有静态数据源，直接展开 shell 自己渲染的菜单树，层级和顺序与真实菜单一致。个别由 MSIX 打包应用注册的项（如「在终端中打开」）在注册表里没有可写的键，会以来源「内建」显示，只读、不能隐藏或调序。
- 选中一项后，底部五个按钮：
  - **隐藏 / 显示**：同一个按钮，选中的项现在可见就是「隐藏」，已隐藏就是「显示」。静态项写隐藏标记；COM 扩展按 CLSID 加入/移出 Blocked 名单，全局生效。
  - **上移 / 下移**：把菜单项**逐位**往上/往下挪一格（不是置顶/置底），挪完状态条会说「现在第 N 位」，真实右键菜单里的次序同步变化。
  - **自定义**：弹「自定义菜单项」小窗，填「菜单项名称」和「命令行」，在当前场景的位置根下加一个静态菜单项（只写 HKCU，来源列显示「自定义」）。可以点「浏览…」选一个程序自动填好名称和命令行，或点 PowerShell / CMD 模板一键填入「在当前目录打开终端」；已添加的项在下半部列出，点一下即删除。命令行里 `%1` 是选中的文件、`%V` 是所在目录。
  - **刷新**：重新读一遍注册表。
- 「可改」列已经把这件事写在表里（`隐藏·调序` / `仅隐藏` / `只读`），下面再解释一遍原因：上移/下移只对**自带显示名（MUIVerb）的静态项**有效。`打开`、`在此处打开 Powershell 窗口` 这类系统内建项，菜单里显示的名字是由 Windows 按动词名硬编码的，一旦改名就会变成 `p0001#open` 这种乱码——所以脚本让它们原地不动，点了会明确告诉你原因。COM 扩展的先后由各自 DLL 决定，也调不了。
- 改完立即广播 `SHChangeNotify`，绝大多数情况不用重启资源管理器。
- 本脚本没有托盘菜单：宿主列表里的齿轮点开是空的，只起前置窗口的作用，不会弹 AHK 默认的 Open/Reload/Edit/Exit 那些项。

## 入口

- 主窗口：左侧选场景或拖入文件 → 右侧选菜单项 → 底部按钮操作。
- `--open <路径>`：直接以「拖入对象」场景打开该文件/文件夹，不用手拖。
- `--selftest [输出路径]`：无 GUI 分支，默认写 `右键菜单整理\selftest-result.txt`。
- `--probe verb <位置suffix> <verb> <动作>` / `--probe com <CLSID> <hide|show>` / `--probe roots <场景key> <结果文件> [拖入路径]` / `--probe items <场景key> <结果文件> [拖入路径]` / `--probe real <路径> <结果文件>` / `--probe order <场景key> <结果文件> <verb,verb,…>` / `--probe restore <场景key> <结果文件>` / `--probe vals <HKCR键路径> <结果文件>`：实机回归用；日常不用。

## 写入位置

只写 HKCU，HKLM 原键一个字节都不动：

- **静态项隐藏**：`HKCU\Software\Classes\<位置>\shell\<菜单项名>` 写 `ProgrammaticAccessOnly = ""`；恢复即删这个值。菜单项来自多个位置时，每个位置的影子键都写，才不会被别的来源重新带出来。
- **位置（只读）**：别人/旧版本写在 `Position` 里的 `top` / `bottom` 仍会被读出来用于推断次序，但本脚本**不再写**它——只有顶部/底部两档，满足不了「逐位」。位置根不含 `\shell`（如 `*` / `Directory\Background`）。
- **静态项顺序**：shell 按 verb **键名字母序**排静态项（与显示名无关），`Position` 只有顶部/底部两档，没有「第 N 位」。所以逐位调序靠「接管」：把该根下的静态 verb 复制成 `HKCU\Software\Classes\<位置>\shell\p0001#<verb>`、`p0002#<verb>`…（前缀 `p` 排在 `open` 之后），原件只写 `ProgrammaticAccessOnly` 让位、显示名与命令都不动。副本编号就是真实次序。恢复 = 删掉所有副本 + 清掉 `ProgrammaticAccessOnly` 与 `_AhkDeckTakenOver` 两个标记。
- **COM 扩展隐藏**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Shell Extensions\Blocked` 写一个值名为 CLSID 的空串；恢复即删该值。

这些值在 `HKCR` 合并视图里可见，于是既能盖住 HKLM 的菜单项，又不破坏它原本的显示名和命令。
`--selftest` 结果写 `scripts/右键菜单整理/右键菜单整理/selftest-result.txt`（同名文件夹，运行时自建，不进仓库）。
GUI 事件层抛的异常会落到同一目录的 `error.log`，排查「点了没反应」先看它。

## 风险与不做

- **不永久删除**任何系统菜单项、不改已有命令、不碰文件关联、不提权、不写 HKLM。隐藏和位置都是可逆的；自己用「自定义」加的项可以随时删掉。
- **系统级隐藏的项恢复不了**：若某项的隐藏标记写在 HKLM（如 `HideBasedOnVelocityId`），零提权删不掉，脚本会如实提示"需管理员权限"，绝不谎称已恢复。
- **系统共享的 COM 扩展拒隐藏**："共享 / 投射到设备 / 还原以前的版本 / 照片编辑 / 包含到库中" 这类 CLSID 由多个功能共用，Blocked 会连带弄坏系统菜单，脚本一律拒写。7-Zip、ima、360、Unlocker 这类独立扩展不受限。
- **不碰 `open` / `edit` 这类打开动词**：它们是文件关联的关键，脚本对这两个 verb 一律不写。
- **不写 `CommandFlags`**：那是 Windows 的功能位掩码，不是开关，写错会弄坏菜单；本脚本只读取它来判断是否已隐藏。
- **不做 Win11 打包命令（IExplorerCommand）**：那是稀疏 MSIX 包 manifest 里的动态命令，不属于注册表静态项，本脚本不覆盖。
- **顺序与二级内容以 shell 渲染出的真实菜单为准**：拖入文件/文件夹时，脚本调 `IContextMenu::QueryContextMenu` 把整棵菜单树读下来（`CMF_CANRENAME` 打开，「重命名」这类标准项才会出现），每一项的 verb 用 `GetCommandString(GCS_VERBW)` 问出来，注册表项与菜单项由此一一对应——列表里的位次和缩进层级就是真实菜单的位次和层级，不靠推断。**写入仍然按注册表来源**——COM 项在真实菜单里是自绘的、连 verb 都没有，反推不出该写哪个键。注册表里有、这次 shell 却没渲染的项标「菜单外」（`Safe360Ext`、`加密`、`Offline Files` 这类扩展会在运行时自己决定不出项）；桌面/文件夹空白场景拿不到确定对象，这一层校验会跳过，回退到按注册表推顺序。
- **「在新窗口中打开」是特例**：它注册在 `Folder\shell\opennewwindow`，但资源管理器会把它从公开菜单接口里滤掉、由自己补上，所以 API 读不到。脚本按 `--probe exmenu` 实测到的位次（紧跟「打开」之后）把它补回列表；找不到「打开」做锚点就不补，宁可少一行也不错位。
- 菜单项显示名取自注册表；个别项的中文名由系统资源串解析，解析不出来时回退为注册表名；常见系统扩展（发送到/新建/打开方式/上传至ima知识库…）走友好名映射。
- **顺序**：静态项的顺序可以真的改，代价是该根下的**有显示名的**静态项会被「接管」——原件留 `ProgrammaticAccessOnly` 让位、由 HKCU 副本出面，所以被接管的项在注册表里会看到 `p000N#…` 这类键名，这是设计如此（脚本里就叫「副本」）。没有 MUIVerb 的内建项（打开/命令窗口/Powershell 窗口）不参与接管，位置由系统固定——这是硬限制，硬改会把菜单显示成键名。COM 扩展之间、以及菜单里那些不在注册表里的内建命令（剪切/复制/粘贴/重命名/属性…）的先后，脚本也改不了。接管只影响当前用户，点「恢复」或 `--probe restore` 即可完全还原。
