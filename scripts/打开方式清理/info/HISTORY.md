# 打开方式清理 历史

只增不改：每次发版在最上面加一段 `## <版本>（日期）`。

## 1.5.4（2026-11-13）

- **修复（1.5.3 仍没修干净）：填表那 700ms 里，空列表右边露着一条原生竖条 + 底部一条横条。**
  1.5.3 的「摘条 → 打开重绘」只处理了收尾那一帧，中间整个过程照样露。真正的原因是
  **`WM_SETREDRAW` 只压得住客户端绘制，压不住非客户区**：行一多 comctl32 就把
  `WS_VSCROLL` 置回并当场把滚动条刷出来；竖条又让客户区窄 16px，按整幅宽算好的列宽
  立刻溢出，横条跟着再冒一条 —— 屏幕上就是「空列表 + 两条原生灰条」，状态栏还停在
  「正在扫描 · 15/15」（填表期间不更新状态）。
- 修法：**填表期间把 ListView 整个 `SW_HIDE`**（隐藏窗口一个像素都不画），填完
  `SW_SHOW` 一次性整幅重绘；`SW_HIDE` 会丢焦点，捕获 `Gui.FocusedCtrl` 后补回 `Focus()`。
  实测同一时刻截图：修前灰竖条 + 灰横条，修后列表区干净白底（只有边框）+ 状态条正常。
- 顺带修正 W8 的判据 bug：它按 `GetClientRect` 算采样带，而客户区**不含**滚动条，
  采样带整整错开 16px —— 之前 W8 报「0 命中」却肉眼能看见灰条就是这个原因。
  改用 `GetWindowRect` 后，同一份 1.5.3 代码 W8 报「最长连续 48 帧 / 16 列灰」，
  1.5.4 报 0 帧。

## 1.5.3（2026-11-13）

- 注：本条「修后最长连续 0 帧」的结论受上面那个 W8 采样带 bug 影响，实测仍会露条；
  真正的修法是 1.5.4 的「填表期间隐藏列表」。

- **修复（1.5.2 没修干净）：进界面仍会闪过原生竖条，而且不是一帧、是近 1 秒。**
  宿主内逐帧实测 + 脚本内打点定位到真正成因：`FillList()` 填 1813 行要 **718ms**
  （日志：1110ms 进、1828ms 出），这期间 AHK 单线程没有空闲，`Sync` 的 60ms 定时器
  只在收尾挤进两拍 —— 也就是说灰条从填表开始一直亮到填表结束。1.5.2 把摘条放在
  `WM_SETREDRAW` 打开**之后**，只能擦掉最后一帧，前面 700ms 照样看得见。
  正解是**顺序反过来**：`LVM_ENSUREVISIBLE`（滚动定位）与焦点也挪进「重绘关闭」
  区间 → 先 `HideNative()` 摘条 → 再 `WM_SETREDRAW` 打开重绘。重绘一开 ListView
  会连非客户区一起重刷，此时样式位已被摘掉，灰条一帧都画不出来。
- 实测（宿主 `AHKDeck.exe --run` 与独立解释器各一遍）：修前灰条可见 1203→2054ms；
  修后新增的 W8 首帧检查报「最长连续 0 帧」，偶发会残留 1 帧（≈10ms，肉眼不可见）。

## 1.5.2（2026-11-13）

- 注：本条记录的「收尾处 Sync()」修法**不完整**，灰条仍会从填表开始亮到填表结束，
  真正成因与正解见 1.5.3。

- **修复：进界面时原生竖条闪一帧**。填表末尾 `WM_SETREDRAW` 一开，ListView
  就把 `WS_VSCROLL` 置回并排一次非客户区重绘，等到 `Sync` 的 60ms 兜底已经晚了
  —— 屏幕上就是「进来闪一下旧滚动条」。修法：`FillList()` 收尾处先
  `gScroll.Sync()`（藏原生条、重算占位、画自绘条），再 `Redraw()`，全部落在
  回到消息循环之前。实测填表返回时样式位 `0x5001400D`，`WS_VSCROLL` 已为 off。
- **修复：`txtfile` 这类类型名显示成乱码中文**。原因不在读法，在取数口：
  `Friendly()` 原来取 `HKCR\<ProgID>` 的默认值，而 Shell 显示类型名根本不用它。
  本机该值是被旧软件写坏的脏数据 —— 「文本文档」的 UTF-8 字节按 GBK 写进了
  `REG_SZ`（`U+93C2 U+56E8 U+6E70 U+93C2 U+56E8 U+3002`），读出来就是
  「鏂囨湰鏂囨。」。改为按可信度排优先级：MuiCache → `FriendlyTypeName`
  （`@dll,-123` 形式用 `SHLoadIndirectString` 解成本地化名称）→ 默认值兜底。
  实测 `txtfile` → `Text Document`、`batfile` → `Windows 批处理文件`、
  `cmdfile` → `Windows 命令脚本`、`pngfile` → `PNG 图像`。
- 内存实测（独立解释器 2.0.30，18 项扫描 1813 行）：本脚本 36.9 MB，
  空列表窗口 25.3 MB，裸 AHK 进程 13.9 MB —— 大头是运行时与 ListView 本身。

## 1.5.1（2026-11-13）

- **修复：滚动后右侧露出原生灰条**。`ScrollToRow` 里的 `LVM_ENSUREVISIBLE` 会让
  ListView 重算滚动范围并把 `WS_VSCROLL` 重新置回，原生条于是露出来
  （实测滚动后右侧出现 16px 的 `F0F0F0`）。修法：每次滚动动作后当场再
  `HideNative()`，不等 `Sync` 的 60ms 兜底。
- **修复：窗口变窄时搜索框不跟随、右侧按钮被裁**。工具行原是纯绝对坐标，
  `OnGuiSize` 只重排列表与状态条，工具行纹丝不动（1100 宽的版式在 820 宽里
  右侧三个按钮整个跑到窗口外）。改成三段式：左侧 3 按钮固定、右侧 3 按钮贴右缘、
  中间搜索框吃余量，`OnGuiSize` 里按客户区宽重算。
  `FlatButton` 返回的是内块，外层描边块另存 `gBtnFrames` 映射，
  新增 `MoveFlatButton()` 让两层一起挪（否则外层留在原地露出旧边）。
- 验证：滚动 6 格后原生灰条像素 0；窗口缩到客户区 820 宽时最右按钮右缘 804
  （= 820 − 16），搜索框右缘紧贴按钮组；双环境一致。

## 1.5.0（2026-11-13）

- **滚轮此前完全不滚（实机复现）**。原生滚动条用 `ShowScrollBar(FALSE)` 隐藏，而它会顺带
  摘掉 `ListView` 的 `WS_VSCROLL` / `WS_HSCROLL` 样式位：摘掉之后 ListView 既不再响应
  滚轮（发 `WM_MOUSEWHEEL`，首行号纹丝不动），也不再响应键盘翻页，滚动范围直接塌成 0。
  改为**自管竖向滚动状态**：行数、可视行数、首行号自己算，滚动一律走 `LVM_ENSUREVISIBLE`
  （实测精确到位，摘掉样式位后依然可用），滚轮与 `PageUp/PageDown/Home/End` 由脚本用
  `OnMessage` 接管。滚轮消息只发给焦点控件，焦点落在搜索框时列表就收不到，所以按
  「窗口内任意控件」处理。
- **最大化再复原后列表右侧留一大块白**。ListView 改列宽后，行底色的绘制范围会停在旧列宽
  的位置（实测条纹长度由满宽 1023px 缩到 478px，且复原后不恢复），整张表看起来像缺了一块。
  改为改完列宽调 `S.lv.Redraw()` 整表重绘；`InvalidateRect + UpdateWindow` 与调换
  `ModifyCol` 顺序都无效（实测）。
- **横向滚动条撤掉**。横向 `LVM_SCROLL` 实测完全不生效（有无样式位都不行，且旧代码把
  `delta` 传给了 `wParam` —— 那里应该是 `SB_HORZ`），那根条一直是装饰品。列宽改为按列表
  可视宽分配，横向不再溢出，也就不需要横向条。
- **新增仓库级回归检查 `tools/ui_regress.py`**：真发滚轮事件、键盘翻页、最大化复原后
  行底色宽度、右缘是否露出原生灰条、调色板一致性、关闭是否退出，逐项断言，
  独立解释器与宿主 `--run` 双环境各跑一遍。

## 1.4.0（2026-11-13）

- **自绘列头（收掉 1.3.0 的一条例外）**：`ListView` 加 `-Hdr` 去掉经典 3D 原生列头，
  列表区顶部改一条 `BAND DCE8F7` 列头带 `h26` + 六个 `s10 Bold` 文字块（写完立刻 `Norm`）。
  每块挂 `Click` → `OnColClick(S.lv, i)`，**排序功能原样保留**；排序状态改由状态条
  事实句「按「扩展名」升序」表达。`HeaderClick(n)` 包一层是为了让箭头函数按值捕获列号，
  直接在 `for` 里写闭包会全部指向最后一个 `i`。`OnGuiSize` 用同一份 `S.colW`
  同步列宽与列头文字块（x = 列起点 + 6，宽 = 列宽 − 12，末列裁到带右缘）。
- **自绘滚动条（收掉另一条例外）**：整段复制 `文件时间修改 2.4.5` 的
  `class FlatScroll` + `HookBarInput`（槽 `BAND DCE8F7`、滑块 `ACCENT 6E9BD4`，
  `ShowScrollBar(FALSE)` 隐原生条、`LVM_SCROLL` 统一滚动、`SS_NOTIFY` + 轮询拖动）。
  只把 `OnBarWheel` 里引用的 `gList` 换成 `S.lv`。窗口可 Resize，故 `OnGuiSize`
  重填 `gScroll.x/y/w/h` 后调 `Layout()`；行数变化由 `UpdateStatus()` 触发一次重算；
  `Close` 与 `Cleanup` 都先 `gScroll.Stop()`（K21）。`--selftest` 在 `BuildGui` 之前
  `ExitApp`，不会创建滚动条，隐藏测试窗口不受影响。
- **唯一剩余例外**：`Checked` 行内勾选框（行数动态、§10 无逐行自绘配方）保留；
  自绘按钮禁用态仍由 `ViewHistory()` / `RestoreHistory()` 的 `if !i return` 兜底。
- **门禁**：解释器 `/validate` rc=0；宿主 `--validate` ok；`--selftest` 19 项 PASS、
  `fails=0`；双环境实机像素逐点复核；MCP 实机闭环。

## 1.2.0（2026-11-11）

- **列排序原地重排**：点表头不再整表重建。排序口径仍由 `SortView`（AHK Sort）给出，行重排交给
  comctl32 `LVM_SORTITEMS`——每条目挂稳定 `eid` 写进 `lParam`，按名次原地搬行，勾选/焦点/滚动随行保持。
  1806 行实测点表头从 ~360–401 ms 降到 ~5–7 ms（约 70×），顺序逐行一致。
