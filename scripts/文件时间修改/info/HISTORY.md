# 文件时间修改 历史

只增不改：每次发版在最上面加一段 `## <版本>（日期）`。

## 2.4.7（2026-11-13）

- **修复：点自绘勾选框会直接崩掉脚本**。`FlatCheck` 把回调存进对象属性后写成
  `this.cb()` 调用，同样被当成「方法」调用并隐式多传一个 `this`，报
  「Too many parameters passed to function」——官方解释器弹错误框，宿主内核终止进程。
  改成显式 `this.cb.Call()`。
- 验证：`tools/ui_regress.py` 新增 S3「点勾选框后状态翻转」（内块底色
  `FFFFFF` → `202B3A`，勾号出现）与 S4「点勾选框后无错误框」，双环境通过。

## 2.4.6（2026-11-13）

- **滚动此前是坏的**。`ShowScrollBar(FALSE)` 隐藏原生条时会摘掉 `ListView` 的
  `WS_VSCROLL` / `WS_HSCROLL`，摘掉之后 ListView 不再响应滚轮与键盘翻页，滚动范围塌成 0
  （实测：`GetScrollInfo` 全 0，发滚轮首行号不变）。改为**自管竖向滚动状态**：
  行数 / 可视行数 / 首行号自己算，滚动走 `LVM_ENSUREVISIBLE`，滚轮与
  `PageUp/PageDown/Home/End` 由 `OnMessage` 接管。
- **横向滚动条撤掉**：横向 `LVM_SCROLL` 实测不生效（旧代码还把 `delta` 传给了 `wParam`），
  路径列宽由 600 改为 376（做进视口），不再需要横向条。
- 仓库新增 `tools/ui_regress.py` 回归检查，双环境跑滚轮 / 翻页 / 条外观 / 关闭退出。

## 2.4.5（2026-11-13）

- **关闭按钮现在真正退出脚本**。2.4.4 的 `Close` 回调只有
  `gScroll.Stop()` + `gGui.Destroy()`：窗口没了，但脚本进程还挂着（宿主里会话一直是 running）。
  文件哈希用 `ExitApp()` 就没这个问题；夜灯是面板 + `Persistent(true)`，关面板只关面板，
  属于另一种正确口径，**不跟着改**。本脚本以窗口为唯一入口、没有托盘菜单，应跟文件哈希一致。
- 改为 `(gScroll.Stop(), ExitApp())`：先停 `FlatScroll` 的 `Sync` 定时器（K21：定时器会让脚本
  活过窗口销毁，下一拍访问已销毁控件会弹「The control is destroyed」），再退出。
- **实测**（`.temp/probe_close.py`，对窗口发 `WM_CLOSE` 后等 1.5s）：
  改前 `文件时间修改 alive=True / exitcode=None`，改后应与 `文件哈希 alive=False / rc=0`
  一致；`夜灯 alive=True` 是设计如此（关面板后托盘仍待命）。
- 行为零改动：拖放、时间写入、勾选、滚动条、状态条全不动。

  现在文字是近黑，中蓝压黑字发闷也显脏。两枚按钮统一成「清空列表」那套 —— 底 `#EBF2FB`、
  边 `#B7C8E0`；动作主次交给位置（右对齐、常用动作靠右）与文案。

  左侧竖排三行的位置形成一串色块，比按钮还抢眼。
- 「路径」区块的外框改成把标题带一起包住：外框从 `y132` 到 `y338` 一整块，标题带与列表都
  内缩 1px 落进去。原先标题带自铺一条浅蓝、列表再自带一圈边框，两条边互不相干，看着像
  「一块色条压在一个框上」而不是同一个区块。列表高度由 179 变 178（让出 1px 给标题带顶边）。

## 2.4.0（2026-11-13）

- 修「拖动滑块时出现断点」：一次重排里有 11 个色块，2.3.9 是逐个 `Move` 的，屏幕上会出现
  「槽已经让位、滑块还没到」的中间帧 —— 拖动是 20ms 一拍，这些中间帧就是一道道断块，
  停下时还会留下孤立的小方块。改为 `BeginDeferWindowPos / DeferWindowPos / EndDeferWindowPos`
  一次提交全部位置，中间帧不存在。
- `Sync` 在拖动中只兜原生条、不再重排色块：它和 `DragTick` 同时画会在同一帧里交叉，
  是断点的另一半来源。
- `ScrollBy` 里隐藏原生条改用 `EnsureHidden()`，样式位已经干净时不再多调一次
  `ShowScrollBar`（少一次列表重绘）。
- 验证：宿主内拖动过程中连续抓 20 帧 —— 2.3.9 有帧出现「主滑块 + 孤立 1px 深蓝」，
  段长在 20/21/30 之间跳；2.4.0 全部单段、长度恒定 29–30。稳态几何、翻页、空列表行为不变。

## 2.3.7（2026-11-13）

- 修 2.3.6 的实质缺陷：**原生滚动条与自绘条同时出现**。`ShowScrollBar(FALSE)` 本身有效，
  但 `ListView` 每次重算滚动范围（`Move`/`Add`/`Delete`/`ModifyCol`/`LVM_SCROLL`）都会把
  `WS_HSCROLL`/`WS_VSCROLL` 置回来，而 2.3.6 的隐藏动作发生在 `Move` **之前**，最后一步
  `Move` 又把它请了回来（实测样式位 `H1V1`）。
- 改为「每次动作后补一刀」：`Layout()` 循环收尾再隐藏一次、`ScrollBy()` 滚完立刻隐藏、
  `Sync()` 每拍检查样式位（60ms，只在 `nPos` 变化时才重排控件）、列表滚轮处理完用 `-1`
  定时器补一次。实测 `Move`/`Add`/`LVM_SCROLL` 之后三处均为 `H0V0`。
- 0 行时不再画横条：空列表的横向溢出只是列宽（600 > 视宽）造成的，没有可滚内容，
  2.3.6 会留一条空滑块在中间。清空列表时顺带把横向位置归零，重新拖入不会看不见路径开头。

## 2.3.6（2026-11-13）

- 列表滚动条改为自绘：原生条由 comctl32 主题引擎画，`WM_CTLCOLORSCROLLBAR` 实测不触发、
  `SetWindowTheme("DarkMode_Explorer")` 也只换浅/深两套外观，拿不到任意颜色。改为隐藏原生条
  （`ShowScrollBar(FALSE)`，保留滚动范围与滚动能力）后自绘：槽 `#E3EAF6`、滑块 `#3C6EB4`，
  与整体配色同一套令牌。
- 交互：拖动滑块（20ms 轮询鼠标位与左键状态）、点槽空白翻页、滚轮落在条上转发给列表；
  滚动统一走 `LVM_SCROLL` 像素增量，滑块位置每帧从真实 `nPos` 反算，键盘与滚轮之后也不会错位。
- 占位行为与原生一致：内容超出才缩列表并显示该轴，最多三轮收敛；清空后列宽自动回满。
- 修掉一个会弹错框的缺陷：定时同步让脚本在窗口销毁后仍存活，下一拍访问已销毁控件会报
  「The control is destroyed」。关闭事件里先停定时器、释放捕获，再 `Destroy()`。
- 版式不变：列表可用内空仍是 `x17 y158 w386 h179`，竖条占右侧 10px、横条占底部 10px。

## 2.3.5（2026-11-13）

- 时间框里的按钮也扁平化：`SysDateTimePick32` 的右侧按钮是**控件内绘**的，经典样式是 3D 凸起按钮
  （控件 124..139），有主题时则是字段内的日历小图标（116..121），`-0x800000` 与主题都动不了它。
  改为把控件裁到只剩文字区（`ClipField` 裁到 115，两种模式都不再绘制按钮），右侧交给自绘白色块：
  日期是 7px 白内边距 + 1px 分隔线 + 17px ▼ 块；时分秒是 1px 分隔线 + ▲/▼ 两块（16px）。
- 点击不落在控件上，所以按**原生按钮坐标**把消息转发回去：日期转发 `WM_LBUTTONDOWN/UP` 到控件
  客户区 (131,14) 打开系统日历；时分秒转发 `VK_UP` / `VK_DOWN`，改的仍是控件当前选中的那一段，
  不自己算时间。转发一律 `PostMessageW`——日历下拉是模态的，`SendMessage` 会把调用栈压进它的
  嵌套循环，实测更难恢复。
- 抽出 `MakeDateField()` / `MakeTimeField()` 两个工厂，六行时间控件不再重复 40 行色块代码。
- 行为零改动：拖放、三种时间独立勾选、递归展开、只有点「更新时间」才写入，全部不变。
- 门禁：真源/出货件 `/validate` 与宿主 `--validate` 全绿；独立解释器与宿主各一张真实窗口像素图
  （4× 放大核对，无灰底/黑三角残留）；自包含探针在两种环境结果一致——点 ▼ 后出现系统日历
  （`SysMonthCal32` / `DropDown`），点 ▲ 后时间 00:59 → 01:59，其余流程与 2.3.4 相同。
- 已知行为：日历下拉是模态的，它开着时脚本自身的语句停摆（宿主主窗口仍响应消息，实测
  `WM_NULL` 不超时），选完或关掉后立即继续 —— 与点原生按钮的体验一致，不是卡死。

## 2.3.4（2026-11-13）

- 勾选框真正扁平化：系统 CheckBox 在宿主（缺 comctl32 v6 manifest）下是经典黑勾方框，样式位去不掉，
  改为 `class FlatCheck` 三层 Text 色块自绘 —— 16×16 #A8BCD6 细线外框 + 14×14 内块 + 文字标签，
  选中时内块填 #3C6EB4 并画白色 ✓（`s11 Bold`，实测笔画约 2px；s10 的「√」只有 1px 线、看不出形状，
  「✔」U+2714 会糊成一团）。`.Value` 仍是 0/1，三处调用点无需改动；点击越框、方块、文字都能切换。
- 日期/时间框真正扁平化：`-0x800000` 去 WS_BORDER 后 SysDateTimePick32 仍自绘 2px 立体边，
  改为四周各外扩 2px 建控件、再用 `SetWindowRgn` 把可见区裁成 (2,2)-(w-2,h-2)，
  立体边被整体裁掉、细线由外层 1px #A8BCD6 底块提供（`ClipControlBorder()`）。
- 版式随之微调：时间列 `x124 w140` / `x272 w132`，控件外扩后可见区仍是 `138` / `130` 宽，
  三列与列头逐像素对齐；勾选框 16px 方块与 26/28 高文字行垂直中心实测同为 85.5 / 388.5。
- 修正一处加载期缺陷：类声明是运行期语句、不会被提升，`class FlatCheck` 原先写在顶层 `return`
  之后，AHK 报「This line will never execute」并弹模态框（连 `/validate` 都会卡住），已移到调用之前。
- 门禁：真源/出货件 `/validate` 与宿主 `--validate` 全绿；独立解释器与宿主 `--run` 各一张真实窗口
  像素图（含 4× 放大核对）；自包含点击探针在两种环境结果一致 —— 三个 DateTime 取值 14 位、
  写入成功 1 项、清空归零、`FlatCheck` 文字与方块两次点击均能翻转 1→0。
- 残留（如实登记）：宿主内 DateTime 自带的日历下拉按钮与时分秒微调箭头仍是经典凸起样式 ——
  那是控件内绘的子按钮，脚本层无法改主题，只能整控件裁边；独立解释器（有 v6 manifest）下为扁平主题外观。
