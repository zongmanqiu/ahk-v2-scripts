## 2.3.1（2026-11-15）

> 本轮拿 dmidecode 上游源码（`dmi_memory_device_type` / `dmi_chassis_type`、
> `dmidecode.c` Type 16/17 分支）与 Windows 移植版 `windmi/windmi.c` 逐字节对照本脚本，
> 查出三处码表/位段的实错。三处都是「本机正好算对、换台机器就错」的类型。

- **修：内存类型码表整段错位**。原表按"顺序"往下排（0x14=DDR、0x20=DDR5…），
  与 SMBIOS 7.18.2 实际码位不符：**DDR5 是 0x22**，原表却是 0x22→HBM3，
  **装 DDR5 的机器会显示成 HBM3**；0x12=DDR / 0x13=DDR2 原表直接缺，
  0x1B–0x1D 的 LPDDR 系列也错了一位。本机是 DDR4（0x1A），恰好是少数对得上的档位，
  所以一直没露馅。现按 dmidecode `dmi_memory_device_type()` 全表重写（0x01–0x24）。
- **修：内存 Rank 取错位段**。Type 17 的 `Attributes`（offset 0x1B）**bit3:0 是 Rank 数**，
  原代码写的是 `(attr >> 3) & 3`（取 bit3:4），单 Rank 条算出来也是 0，靠码表里
  `0 → "1R"` 的补偿显示成了 1R；**双 Rank 条会同样显示 1R**。改为 `attr & 0x0F`，
  并把 `0` 如实显示为「未填」（主板没填该字段）。
- **修：机箱类型 17 之后错位**。0x11 起原表把「多系统机箱 / 紧凑型 PCI / 高级 TCA / 刀片」
  提前拼进了 0x12–0x15，导致「扩展机箱 / 子机箱 / 总线扩展机箱 / 外设机箱 / RAID 机箱」
  全部对错位；现补齐 0x01–0x24（含平板、迷你主机、U 盘式 PC 等常用新档位）。
- 顺带补全**内存封装**码表（WMI `FormFactor` 用 CIM 枚举，8=DIMM、12=SODIMM，
  与 SMBIOS 的 9/13 差一位，两者不能混用——已在注释里写明）。
- 自测 **33 项**：内存类型码改断言 `0x1A=DDR4 / 0x22=DDR5 / 0x20=HBM / 0x12=DDR`，
  Rank 码改断言 `1→1R / 2→2R / 0→未填`，另加「实机内存条读到了非零 Rank」一项。

## 2.3.0（2026-11-15）

- **新：显存显示真实值（6 GB）**。`Win32_VideoController.AdapterRAM` 是有符号 32 位，
  6 GB 卡只会给 4095 MB 甚至负数——这是 WMI 的老毛病，不是取值错。改从显卡驱动在注册表
  `Class\{4d36e968-…}\000X\HardwareInformation.qwMemorySize` 登记的 **REG_QWORD** 读，
  按 `MatchingDeviceId`（`PNPDeviceID` 前缀）配对适配器。实测 GTX 1660 SUPER = 6442450944 字节，
  显示「6 GB」。`RegRead` 读不了 REG_QWORD（报 1630），自己调 `RegQueryValueExW`。
- **新：显卡 vBIOS 版本与芯片名**（同键的 `BiosString` / `ChipType`），芯片与名称相同时不重复列。
- **新：CPU 家族/型号/步进**。WMI 只给 `ProcessorId`，后 8 位就是 CPUID 叶 1 的 EAX：
  `BFEBFBFF00090672` → 家族 6 / 型号 151 / 步进 2。
- **新：CPU 指令集**。走 `kernel32!IsProcessorFeaturePresent`（内核判定，与 CPUID 同源，
  不用写机器码）：本机列出 MMX / SSE / SSE2 / SSE3 / SSSE3 / SSE4.1 / SSE4.2 / AVX / AVX2 /
  RDRAND / RDTSCP / XSAVE / SLAT。
- **新：显示器接口**（`WmiMonitorConnectionParams.VideoOutputTechnology`）：本机 HDMI。
- **修：硬盘「接口」显示成 SCSI**。NVMe 盘在 WMI 里一律报 `SCSI`，改为从 `PNPDeviceID`
  的 `VEN_NVME` / `USBSTOR` 判总线，本机显示「总线：NVMe」。
- 自测 33 项（新增 ProcessorId 解码、6GB 显存、接口码、指令集、NVMe 总线判定）。

  省下的 40px 直接给了列表。实测导航项 76×28、文字完整不裁。
- **修：多显示器时「屏幕尺寸」会串台**。尺寸来自 `WmiMonitorBasicDisplayParams`（另一个类），

- **修：双路主板只显示第一颗 CPU**。`Win32_Processor` 的遍历里写了 `break`，第二颗直接被丢掉。
  改成全部收集（`cpus` 数组），每颗各自成块「── 处理器 N ──」，核心数/插槽/处理器 ID 各算各的。
- **自测扩到 27 项**：新增「两台显示器各自成块、尺寸不串台」「两块网卡各自成块」「双路 CPU

## 2.2.0（2026-11-15）

- **修：列表右侧那条蓝灰色竖块（还有底部一条横带）**。根因不是滚动条画错了，而是**外框用了
  一整块 `FRAME` 打底**：原生 ListView 在列宽之外与空白行不保证重绘，被摘掉的原生滚动条
  留出的 17px 未绘区就露出了底下那块灰蓝（截图实测：白区止于 x=631，632..648 全是 `FRAME`，
  底部 491..507 同样）。改法照《打开方式清理》1.4.0 的做法——**白底块 + 四边各一条 1px
  `FRAME` 线**（§10.4「色块当线」），漏出来的地方与列表同色，看不见。实测列表内区 `FRAME`
  占比从 4.96% 掉到 0.00%。
- **修：首次进内存页时滚动条不出现**。`ScrollToRow` 里重新 `Measure` 了一次，而
  `LVM_GETCOUNTPERPAGE` 在「列表刚 `Move` 完」那一拍会回**过期值**（468 高的列表报 25 行），
  `exV` 被判成假，滚动条当场被抹掉。改为：行数/可视行数只由 `Layout()` 维护，切页与填表都
  先 `Layout` 再进来，`ScrollToRow` 不再自己量。
- **新：窗口可缩放、可最大化**（`+Resize +MinSize560x400`）。值列里有长文本（显卡设备 ID、
  网卡名称），拉宽才看得全。`OnSize` 里先排白底块/四条线/列头带，再定列表尺寸，最后按
  **可视宽**分配列宽（按窗口宽算会多出 10px 溢出到滚动条上），改完列宽 `Redraw()` 一次。
  实测最大化：列头带 518 → 1766、列表 518 → 1766 同步跟随；恢复后回到 672×520。
- **修：最大化后列头带停在旧宽度**（右侧露出白底）。静态色块的背景色走
  `WM_CTLCOLORSTATIC`，只改几何不会重画；逐个 `InvalidateRect`，**不要整窗 `Redraw`**
  ——那个在拖边框时会整屏闪。
- **显示器厂商码不再翻译**：上一版把 `XMI` 显示成 `XMI（小米）`，这是脚本替用户下结论。
  现在原样输出系统给的值（`XMI`、`LEN`、`HWP`…），品牌归属由使用者自己判断。

## 2.1.3（2026-11-15）

- **修：列表顶部框线消失**。2.1.2 为了躲开「漏画区露灰蓝」把外框改成三条线，把顶线也去掉了，
  违背 §10 K27。这次按规范**恢复成一整块外框**（`外框高 = 列头 26 + 列表高 + 2`，列头带与
  列表各内缩 1px 共用同一条线），顶线随之回来（实测客户区 y=12、510px 连续 `FRAME`）。
- **修：滚一下冒出老式滑块**。`LVM_SCROLL` 会把 `WS_VSCROLL` 置回来（K22），之前只在 60ms 的
  `Sync` 里兜底，滚动那一瞬原生灰条就露出来了。改为**滚动前压一次、滚完再压一次**
  `ShowScrollBar(FALSE)`。实测连续 5 次滚轮，样式位全程无 `WS_VSCROLL`。
- **网卡页改成硬件视角**：原来查 `Win32_NetworkAdapterConfiguration WHERE IPEnabled=True`，
  那是「网络配置」视角——没配 IP 的网卡会整个消失，显示出来的 IPv4/网关/DHCP 也都是系统配置，
  不属于硬件规格。改为遍历 `Win32_NetworkAdapter WHERE PhysicalAdapter=True`，只列
  名称 / 适配器类型 / MAC / 连接速率 / 连接状态（是否连接也算硬件状态）。
  页签名同步由「网络」改为「网卡」。
- **显示器厂商码补中文**：`XMI` 不是错的——EDID 的厂商字段是 3 字母 PnP ID（小米 = XMI，
  联想 = LEN，惠普 = HWP，三星 = SAM）。原码照旧保留，认识的补中文并列显示：
  `XMI（小米）`；认不出的只显示原码，不猜。
- 代码里划出 **UI 组件区** 并标注同步来源：本脚本界面元素都从这一区取，改样式只动这一区；
  滚动条与《文件时间修改》2.4.6 的 `class FlatScroll` 同源。按 §10.1，**不得抽公共
  `#Include` UI 库**（会破坏单文件分发模型），跨脚本统一靠「同一份实现 + 逐字同步」。

## 2.1.2（2026-11-15）

- **修：滚到底时最后两行仍被灰蓝色块挡住**。根因是外框用**一整块 `FRAME` 色块打底**、
  ListView 盖在上面——只要 ListView 有一块没重绘到，就露出整片显眼的灰蓝。
  改为只画**三条 1px 线**（左、右、下，列头带本身当上边框）。这样即便有漏画，露出的也是
  窗口底色 `BG`，与列表白几乎看不出差别。（2.1.1 的强制重绘只治了标，这次改的是
  让「露出来」本身不可见。）
- **修：没有可滚内容时滚轮也让窗口闪一下**。两处：① `Repaint()` 原带 `RDW_ERASE`，
  会先把客户区擦成父窗口底色再画，每次滚轮都闪一次白 —— 去掉 ERASE，只留
  `RDW_INVALIDATE|RDW_UPDATENOW`；② `ScrollToRow` 在位移为 0 时仍会 Repaint，改为
  位移为 0 直接返回，只对齐滑块。另给列表加 `LVS_EX_DOUBLEBUFFER` 双缓冲。
  实测：显示器页（6 行，无滚动条）滚轮前后、内存页在顶部继续上滚，两张截图**逐字节相同**。
- **修：右键菜单跑到屏幕右下角**。AHK v2 的 `Menu.Show` 签名是 `Show([Callback, X, Y])`，
  第一个参数是**回调**不是坐标——按 v1 习惯写 `Show(x, y)` 会让 x 当 Callback、y 当 X。
  改为 `Show()` 不传参，由系统在鼠标位置弹出。实测菜单左上角与光标的偏移为 `(0, 0)`。

## 2.1.1（2026-11-15）

- **修：列表上半部被一块灰蓝色挡住**。那是外框底块从「ListView 没重绘到的地方」露出来——
  原生滚动条被隐藏后，ListView 自己算不准要重画的范围，滚动或切页后常留一整块没画到。
  `FlatScroll` 加 `Repaint()`：每次 Layout / 滚动后 `RedrawWindow(RDW_INVALIDATE|RDW_ERASE|
  RDW_UPDATENOW)` 强制整块重画。
- **修：列表底部没有外框线**。列表高度原与外框同底，最后 1px 把底线整条盖掉。列表高改为
  `LIST_H - 1`，让出 1px，底线才露出来。
- **新增：右键复制**。列表右键弹出菜单「复制此行」「复制本页全部」；右键点中的那一行会先被
  选中（原生 ListView 右键不改选中，不选中的话用户不知道在复制哪一行）。另支持 `Ctrl+C`
  复制当前选中行。复制格式为 `属性<TAB>值`，粘到 Excel 正好两列；分隔行（`── A1 槽 ──`）
  与空行按原样输出。复制后弹 1.2 秒浮动提示。
- 实测两个坑：① `WM_RBUTTONUP`（0x205）收不到——ListView 收到右键按下会自己做 `DragDetect`
  内部循环，抬起消息被它消化，所以菜单改挂在 `WM_RBUTTONDOWN`（0x204）并吃掉该消息；
  ② 菜单是模态的，直接在消息处理里 `Menu.Show` 会卡住当前消息、主窗口来不及重画（表现为
  菜单背后列表只画出前几行），改由 30ms 定时器异步弹出。
- `--selftest` 加 3 项复制格式断言；`test/run.py` 加 2 项端到端（EnumWindows 找 `#32768`
  菜单窗口 + 真实鼠标点首项 + 读剪贴板校验）。

  4. `IsChild(parent, parent)` 返回假，鼠标压在导航区/列表外时滚轮消息被丢弃，
     补上「hwnd 等于主窗口」这一支。
- `--selftest` 扩到 20 项；`test/run.py` 扩到 23 项（含窗口 672×520、无标题行/按钮/状态条、

## 1.0.0（2026-11-15）

- 首个版本。概览给出 CPU／主板与 BIOS／内存总量与主板上限／ECC，逐槽列出内存条
  容量、频率、厂商、型号、Rank。
- 数据双源：WMI 取静态信息，SMBIOS 原始表补 WMI 不暴露的 Rank。两者都免管理员、免驱动、免联网。
- 频率列区分标称与实际：降频时显示 `3200→2667 MT/s`。
- 槽位名解析覆盖两种固件形态：多控制器（→ A1/B1）与单控制器双通道（→ A1/B1），重名自动去重。
- 列表高度随条数伸缩（2~8 行）。
- 按 开发指南 §10 落地原生 UI；实测修正 `Gui.Move` 用外框尺寸、`Gui.Show` 用客户区尺寸的坑。
- 安全边界：不读 SPD，故不提供时序/颗粒厂/XMP/EXPO/SPD 温度。
